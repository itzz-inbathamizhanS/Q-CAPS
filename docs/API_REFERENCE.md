# API reference and integrations

Every HTTP endpoint Q-CAPS exposes, who may call it, and every external service it depends on. Real request/response
samples (tokens and passwords masked) are in [api-samples/](api-samples/INDEX.md); regenerate them with
`python backend/scripts/capture_api_samples.py`.

Interactive documentation is generated by FastAPI from the code: run the API and open `http://localhost:8000/docs`
(Swagger UI) or `/openapi.json`. The hosted API serves the same pages at `https://qcaps-api.onrender.com/docs`.

## Conventions

- **Base URLs.** Main API: `http://localhost:8000` locally, `https://qcaps-api.onrender.com` hosted. Scanner:
  `http://localhost:5000` locally, `https://qcaps-scanner.onrender.com` hosted.
- **Authentication.** `POST /api/auth/login` returns a JWT (HS256, signed with `QCAPS_JWT_SECRET`). Send it as
  `Authorization: Bearer <token>`. The scanner validates the same tokens.
- **Authorization.** The user is always taken from the token. Routes with `{user_id}` in the path return 403 unless it is
  the caller's own id (admins excepted where noted). Admin routes require `role = admin`.
- **Errors.** FastAPI returns `{"detail": "..."}` (422 for validation errors, with field details). The scanner returns
  `{"error": "..."}`.
- **Server authority.** Quiz scores, XP, badges, checkpoint grading and progress counters are computed on the server.
  Answer keys are never sent before an answer is locked.

Auth column: **public** = no token, **user** = any signed-in user, **own** = signed-in and the path id must be yours,
**admin** = admin role.

## Main API (FastAPI, `backend/main_api`)

### Identity

| Method | Path | Auth | Purpose |
|---|---|---|---|
| GET | `/` | public | Service banner |
| GET | `/api/health` | public | Liveness check for the host |
| POST | `/api/auth/register` | public | Create a learner (`name`, `password`); password stored as a hash |
| POST | `/api/auth/login` | public | Returns `access_token`; rate limited per address and user name |
| GET | `/api/auth/me` | user | The signed-in user, XP and level |
| GET | `/api/users/{user_id}/profile` | own | Profile |
| POST | `/api/users/{user_id}/progress` | own | Store UI progress; server-owned keys (XP, scores, badges) are stripped |

### Quizzes and diagnostics

| Method | Path | Auth | Purpose |
|---|---|---|---|
| POST | `/api/quizzes/{module_id}/attempts` | user | Issue a shuffled quiz form without answer keys |
| POST | `/api/quizzes/attempts/{attempt_id}/answers` | user | Lock one answer and get feedback |
| POST | `/api/quizzes/attempts/{attempt_id}/submit` | user | Grade on the server; returns score, percentage, XP |
| POST | `/api/quizzes/submit` | user | **Disabled (410).** Legacy endpoint that trusted client scores |
| GET | `/api/diagnostic/results` | user | Graded diagnostic attempts with per-domain results |

### Course content

| Method | Path | Auth | Purpose |
|---|---|---|---|
| GET | `/api/content/tracks` | user | Tracks and modules |

| GET, POST, PATCH, PUT, DELETE | `/api/admin/content/...` | admin | Course editor: tracks, modules, sections, reorder, audit log |

### Skills, recommendations, leaderboard

|---|---|---|---|

| GET | `/api/users/{user_id}/capabilities` | own or admin | Per-competency capability estimates |

## Scanner API (Flask, `backend/scanner_api`)

| Method | Path | Auth | Purpose |
|---|---|---|---|
| GET | `/api/health` | public | `{"status": "ok", "scanning_enabled": true}` |
| POST | `/api/domain-verification` | user | DNS TXT record that proves domain ownership, and whether it is published |
| POST | `/api/scan` | user | `{"url": "example.com", "mode": "standard" \| "full"}`. `full` (active checks) requires verified ownership |

Every scan target is validated against private, loopback, link-local, reserved and cloud-metadata ranges (IPv4, and IPv6 including IPv4 addresses embedded in IPv6; cloud metadata at 169.254.169.254 is link-local), and connections are pinned to the addresses validated once, so DNS rebinding cannot redirect them. Scans are
rate limited per user (`SCANNER_RATE_LIMIT` per `SCANNER_RATE_WINDOW_SECONDS`) and capped by `SCANNER_MAX_CONCURRENT`.
Details: [architecture/SCANNER.md](architecture/SCANNER.md).

Example request (token masked):

```http
POST /api/scan HTTP/1.1
Host: qcaps-scanner.onrender.com
Authorization: Bearer ***MASKED***
Content-Type: application/json

{"url": "example.com", "mode": "standard"}
```

The response contains the DNS, WHOIS, TLS, certificate, header and key-exchange results plus a signed `receipt`; the
frontend forwards both to `POST /api/scanner/log`, which rejects results whose receipt does not verify.

## External services and libraries

| Component | Used for | Where configured | Secret (never in git) |
|---|---|---|---|
| Vercel | Hosts the React frontend (`q-caps.vercel.app`) | `frontend/vercel.json`, Vercel project env | none |
| Render | Hosts the main API and the scanner (free plan) | `render.yaml` | `QCAPS_JWT_SECRET` (generated by Render), admin and demo passwords |
| Supabase Postgres | Production database (users, attempts, progress, scans) | `QCAPS_DATABASE_URL` on Render | database password inside the URL |
| GitHub Actions | `keep-alive.yml` pings the hosted services so the free tier does not sleep during demos | `.github/workflows/keep-alive.yml` | none |
| PyJWT | Signs and verifies access tokens and scan receipts | `QCAPS_JWT_SECRET` | yes |
| passlib | Password hashing | none | none |
| SQLAlchemy, psycopg | ORM and Postgres driver | `QCAPS_DATABASE_URL` | yes (hosted) |
| reportlab | PDF scan reports | none | none |
| dnspython, python-whois, cryptography, requests | DNS, WHOIS, certificate parsing and HTTP checks in the scanner | none | none |
| React, Vite, Zustand, React Router, Recharts | Frontend UI, build, client state, routing, charts | `frontend/.env.example` | none |

No third-party API keys are used: DNS, WHOIS and TLS data come from direct protocol queries, not paid intelligence
feeds. Nothing in the scanner output is simulated; anything simulated elsewhere (labs, missions) is labelled
`SIMULATION` or `DEMO DATA`.

All environment variables are listed, without values, in [backend/.env.example](../backend/.env.example) and
[frontend/.env.example](../frontend/.env.example).
